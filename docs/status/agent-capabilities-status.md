# 智能体命令与扩展能力状态

- 模块职责：把 app-server 的 Skill、MCP、上下文压缩、目标、计划和 Review 映射为 Composer `+` 菜单与 `/` 快捷命令体验。
- 列表更新：Skills 列表顶部不提供手动刷新按钮；进入页面、扩展 revision 变化及安装／卸载后仍自动读取列表，Skill 启停后重新读取有效状态。读取失败保留错误，可退出后重新进入页面重试。
- 当前状态：CS 只提供 Skill 管理和 MCP 配置。Skill 目录提供兔子生图 `image-gen`、高德地图 `amap` 和 `cs-docs`；用户本地 Skill 安装、Core 启停和可恢复卸载、MCP 配置与 OAuth 保留。插件市场、插件安装／卸载及插件详情不再属于 CS 产品功能；Core 的插件协议类型仍随生成协议保留，供运行时兼容，不由壳子调用。
- Skill 详情：技能列表整行点击进入正文详情，正文读取、资源管理器定位和 `skills/config/write` 均使用实际 Skill 路径。初次加载或刷新失败时禁用开关，写入采用 `effectiveEnabled` 并重新读取有效状态。内容弹窗支持关闭、Escape、外部点击与焦点恢复。
- 内置高德地图：`amap` 复用现有安装及可恢复卸载，按隔离 CODEX_HOME 的实际路径识别，安装前后固定在 CS 内置组，保留同名个人技能。包内使用 Bun 脚本、中文元数据和 Windows 示例；依赖外部 Bun 与 AMAP_MAPS_API_KEY，不包含用户密钥、不覆盖已有安装。CS 文档仍固定在系统组，实际 Core scope 不变。
- 最近变更：内置 image-gen 对每项配置依次读取进程、Windows 用户和系统环境变量中的非空值；仅 TUZI_API_KEY 必填，TUZI_BASE_URL 默认 https://api.tu-zi.com/v1。注册表读取失败与配置缺失分开报错，wrong_endpoint_for_model 明确提示协议或令牌路由不匹配，不自动重试或换模型。请求异常及结果记录对注册表取得的密钥同样脱敏。
- 固定排序：Skill 列表将已安装与未安装的内置项合并到固定位置，CS 内置组为兔子生图→高德，系统组 CS 文档置前；其余 Skill 按 name/path 排序。安装状态、启停状态和 Core 返回顺序不参与排序，搜索仅过滤。
- 内置资源与简介：三项内置 Skill 按 `_up_/bundled/skills` 读取，只有 Debug 允许源码回退。高德未安装卡片、已安装列表及详情共用出图能力简介，搜索支持“时间表”。
- 高德出图：真实底图行程模板输出 PNG、图片型 PDF、预览及数据记录；另需 Python、Pillow 和中文字体。缓存参数不符或缺少记录时拒绝复用，支持公交、地铁、步行、骑行和示意段，带路线底衬、线型图例及总览／详情页工作流。
- 查询边界：地址路线多候选退出码为 6，保留候选并停止路线请求；驾车支持 v3 strategy（0–20）和最多 16 个有序途经点，POI 分页仍限制同一查询 200 条。出图不自动核实出行日运营、价格或房态，不是路线优化器。
- 办公实现：办公能力后续应以独立 Skill 形式接入；CS 不再提供插件市场、插件安装或插件缓存迁移。
- 安装与脚本边界：内置 Skill 安装成功但默认关闭失败时仍刷新真实状态并保留错误；读取错误与操作错误分离。高德超时覆盖正文、永久错误不重试、临时错误退避且日志脱敏；已安装独立 Skill 不被应用更新覆盖。
- 草稿行为：选择草稿末尾的 `/skills` 等无参数快捷命令时只移除命令片段，保留正文、图片批注文字和附件；Escape 仅关闭斜杠菜单，不清空草稿。`+` 菜单继续保留全部输入。扩展变更刷新与失效 Skill 选择清理行为不变。
- 当前接口：`ComposerAddMenu`、`ComposerIntentControl`、`SlashCommandMenu`、`SkillPicker`、`McpStatusPanel`、`ReviewPanel`、`useAgentCommands` 及固定协议 RPC 包装。
- 能力边界：Plan 在 `turn/start` 客户端封装中使用局部适配；生成协议与兼容门禁包含实验类型，但不代表产品启用所有实验能力，具体策略与 Runtime 限制见 [协议状态](protocol-status.md)。Codex Core 从模型元数据动态决定自动压缩阈值：缺省为原始上下文窗口的 90%，模型或配置提供的更低值优先且不会超过 90%；Codex Shell 不设置、不复制也不触发该阈值，只展示 app-server 上报的实际用量。独立 CODEX_HOME 只会列出安装到 Codex Shell 环境的 Skills 和 MCP 配置，不自动读取官方 Codex 用户目录。
- 已知问题：办公类 Skill 的 Python、LibreOffice 等依赖由各 Skill 自行声明，CS 不负责分发或验证。Google Workspace、Excel Add-in 和实时 Excel 控制依赖官方账户与工具，不作为 CS 内置能力。复杂办公文件和视觉质量仍需实际验收。新增或替换 MCP Token 仍需任务结束后手动重启 Runtime；命令面板未实现焦点陷阱。
- 下一步：在干净 Windows 环境评估办公依赖分发成本，补独立 LibreOffice 的真实转换和复杂 Office 文件验收；继续验证第三方 MCP OAuth 与 Windows 凭据写入。
