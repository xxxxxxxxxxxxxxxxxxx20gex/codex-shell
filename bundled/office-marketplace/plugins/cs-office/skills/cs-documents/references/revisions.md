# 批注与修订

## 批注

python-docx 1.2 及以上提供 `Document.add_comment`。锚定用户指定的运行范围，设置明确作者和内容。范围横跨部分文字时先在副本中正确拆分 run，保留字符格式；不通过重置 paragraph.text 消除原有链接、批注或修订。

保存后检查 `word/comments.xml`、正文中的 commentRangeStart/commentRangeEnd/commentReference、关系及 Content Types，确认 ID 对应且锚点完整；重新打开时核对数量和内容。仅看到评论文本不证明 Word 可识别批注。

## 修订

python-docx 没有完整的修订编辑接口；普通文本替换不会记录修订。需要真正的修订时在副本的 OOXML 中局部操作，使用 lxml，并保留未修改的 ZIP 部件：

- 新增内容放入带 `w:id`、`w:author`、UTC `w:date` 的 `w:ins`；删除内容使用 `w:del` 和 `w:delText`。
- ID 在已有修订基础上分配，保持已有作者/时间与格式；不能将用户未要求的修订全部接受或拒绝。
- 对现有复杂修订、表格结构变化、字段和嵌套范围，先检查 XML 关系。无法可靠处理时说明限制，可提供修改建议或用户同意的无修订副本。
- 验证新增/删除记录的文字、ID、作者和时间；比较接受修订与保留原文的预期结果。渲染器可能仅显示接受后的视图，不能用 PNG 证明交互修订功能正确。

只有实际创建并核对这些结构，才能宣称已添加批注或修订；复杂结果需在 Word 中验收。
