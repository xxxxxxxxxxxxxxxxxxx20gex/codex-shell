# 真实地图旅游路线图模板

适用：把已规划的行程放到真实地图上，附景点、交通方式、住宿、吃喝和时间表。调用高德地图与本地绘图，不调用生图服务。用户只需要路线查询时，不必加载此模板。

## 文件与执行

- `../scripts/travel_map.py`：Python 3 + Pillow，生成 PNG、PDF、半尺寸预览和可追溯 JSON。PDF 为图片型，不是可编辑矢量地图。
- `../assets/travel-map/hangzhou-example.json`：可复制改写的完整行程配置。
- `../assets/travel-map/hangzhou-geometry.json`：杭州实际查询陆路轨迹与单独标注的游船示意。示例数据查询于2026-09-17，不代表其他日期的交通、房价或船班。

将示例两个 JSON 复制到任务工作目录，修改配置；相对路径以配置所在目录解析。不要把用户行程写回技能示例。首次运行下载底图，并生成同路径 `.png.json` 参数记录；只有 center、zoom、size、scale 一致才复用缓存。改变范围，或旧缓存没有参数记录时，使用新的 `map.image` 路径重新下载，不手工补参数记录来绕过校验。缓存图片与参数记录成对保留，支持后续离线绘图。

```text
python <skill目录>/scripts/travel_map.py --config <工作目录>/plan.json --out <工作目录>/travel-map-v1
```

需要 Pillow（`python -m pip install Pillow`，仅缺依赖时安装）。下载底图需要进程环境变量 `AMAP_MAPS_API_KEY`；脚本不把密钥放进配置、输出或报错。若当前进程未继承 Windows 用户变量，可在 PowerShell 当前会话显式读取，不打印值：

```powershell
$env:AMAP_MAPS_API_KEY = [Environment]::GetEnvironmentVariable('AMAP_MAPS_API_KEY', 'User')
```

仅在进程确实缺少变量时使用上述命令，不覆盖已有有效配置。底图接口失败就停止并报告，不伪造底图、不用生图替代；已有缓存可离线渲染。输出前缀必须是新的，不覆盖旧成果。

## 推荐流程

1. 从已知行程取日期、往返车站、住宿约束与交通偏好；合理缺省可明确说明，不把杭州示例的酒店、日期和价格当作通用默认值。
2. 使用 `poi-text`、`poi-detail` 确认具体门店和入口。位置确认后用 `*-route-coords` 查询各段，保存原始 JSON。地图中展示的交通方案须与选中的路线一致；不要用公交方案轨迹冒充地铁。v3须 `status="1"`，v4须 `errcode=0`，仅成功响应可抽取轨迹。
3. 逐段整理几何数据（格式见下）。默认顺序来自已经审定的行程，不是自动最优路线。查询估时和行程安排时间分开，加入站内步行、候车和游览余量。
4. 选择范围、中心和zoom。总览讲清跨区交通，景区详情讲清出入口、上下船与步行衔接；点位密集或引线过长时，复制配置另做放大页，并只保留范围内路线和日程。当前一次绘制一个地图面板，不自动嵌套放大图，不自动生成路线或拉取全部POI。
5. 填时间表、住宿、餐饮和费用状态，摆放标签。标签默认只写编号和地点，时间集中在右侧；仅登车、登船等关键节点按需在地图重复时间。无住宿时横条可写往返与交通约束。将待确认事项放在对应日程旁，底部保留一般限制和来源。先渲染预览；脚本只检查标签框互撞，无法判断引线遮挡、字形缺失或底图错位，需要视觉检查。
6. 查看至少三个分散的地标与路线是否贴合底图（例如车站、桥梁、湖岸）；查看密集区域、底图署名和全部文字。交付高清PNG、PDF和预览；保留同名JSON与源配置，便于复查和修改。

## 配置格式（version=1）

配置为标准 UTF-8 JSON，无注释。示例展示完整结构：

| 字段 | 用途 |
|---|---|
| `coordinate_system` | 固定 `GCJ-02`。不要混入未经转换的 WGS84/BD09 坐标 |
| `title`, `subtitle`, `lodging` | 标题、副标题、住宿横条；住宿最多约两行 |
| `font` | 可选，中文字体路径；默认尝试微软雅黑、Linux Noto CJK；换系统时确认中文覆盖 |
| `map.image` | 真实底图缓存路径；不存在时请求高德staticmap |
| `map.center` | `[经度,纬度]` |
| `map.zoom`, `map.size`, `map.scale` | 请求底图参数；当前模板使用正方形底图，示例1024×1024、scale=2 |
| `map.zoom_offset` | 静态底图与256px Web Mercator世界像素级别的校准偏移，见下文；不能凭PNG尺寸猜测 |
| `geometry` | 几何JSON路径，相对配置目录或绝对路径 |
| `points` | 每项 `id`、`location`、`label`、`label_xy`、`color` |
| `points[].label_xy` | 标签左上角，相对2048×2048输出地图面板的像素；不是经纬度 |
| `sections` | 任意日期/主题区块，每项 `title`、`color`、`items`；item含`time`、`text` |
| `legend`, `notes` | 颜色含义与下方备注，须说明示意范围；脚本按实际出现的交通模式绘制线型图例 |
| `footer` | 最多3行，每行应控制在画布宽度内，放来源、查询日期与限制 |

画布固定3360×2860：左侧2048×2048真实底图，右侧时间表，顶部住宿，底部图例与来源。文本超出时精简或拆页；标题、副标题和footer目前不会自动缩字号，需视觉检查。

### 关键：静态图缩放校准

杭州实测静态图请求 `zoom=12,size=1024*1024,scale=2` 返回2048×2048图，匹配 `256 * 2**(zoom+1)` 的逻辑世界像素投影，即示例 `zoom_offset=1`。脚本再按输出面板大小/逻辑请求size缩放坐标；scale是底图像素密度，不再重复乘一次。

这是已验证响应的校准参数，不承诺所有渠道和参数都不变。新范围或接口变动时，以三个地标检查；不能只看图像宽高就认定投影正确。尺寸不符、点位出界时脚本拒绝输出。不得通过随意平移单个标签掩盖点位/路线整体偏移。若确需换底图供应商，需要另外实现坐标转换与投影，不能套此配置。

## 几何格式与提取

```json
{"routes":[
  {"mode":"walk","day":1,"color":"#c75436","source":"route_walk_A_B.json","queried_on":"2026-09-17","points":[[120.15,30.25],[120.151,30.251]]},
  {"mode":"schematic","color":"#80579b","note":"游船示意，非实际航线","points":[[120.16,30.25],[120.145,30.239]]}
]}
```

- `walk`/`bike`：v3 `route.paths[选中方案].steps[].polyline`；v4骑行是 `data.paths[选中方案].steps[].polyline`。每个step可以独立一条记录。
- 公交规划：`route.transits[选中方案].segments[]` 中，`walking.steps[].polyline`记为walk；所选`bus.buslines[]`轨迹确认为地铁才记为metro，普通公交记为bus。不根据字段名推断交通类型；接口能返回路线不等于出行日已运营。
- polyline的`;`分点、`,`分经纬度，保留API给出的顺序。`mode`控制线型，`color`控制日程或交通颜色。支持metro实线、walk点线、bike长虚线、bus长划线、schematic虚线；所有路线带白色底衬，图例使用同一绘制逻辑。颜色图例用 `legend` 描述日期或交通颜色，避免手写一套不同的线型说明。
- 原始API路线常包含景区出入口步行、阶梯或步行街。骑行须以允许通行路段为端点单独查询，不把完整API路径视为假日通行许可。
- 水上段没有实际航线数据时，只允许画明确标注的schematic；有无下船权限、船票是否上岛、码头末班需另外核实。不假装沿直线航行。

## 动态信息边界

POI中的距离可能是直线距离，酒店到地铁出口应单独查walk。高德评分不是实地品质验证，POI营业时间不等于节日公告；无指定日期房价与余房时只写位置候选和预算目标。景区免费不代表不拥挤，付费不代表免排队。未知内容标待确认，不编造网上推荐、预约成功或真实排队时长。

模板已用杭州历史真实底图离线验证PNG/PDF输出与标签校验；API未来可用性、价格和临时管制仍需任务当时核查。
