# 网络与错误排查

本文件参考个人 imagegen 的网络文档，按固定兔子渠道和 Windows 环境适配。

## 连接与权限

脚本访问 https://api.tu-zi.com/v1，不读取 OPENAI_BASE_URL。图片还需要访问渠道返回的 CDN 主机。
网络是否可用和是否需要审批是两回事。审批关闭不代表网络已开启；以当前运行环境授权为准，不为排障擅自修改 Codex 全局配置或降低权限限制。

本机有可选代理：

```powershell
$env:HTTPS_PROXY = 'http://127.0.0.1:7897'
```

httpx 读取标准代理环境变量。代理只在当前进程及子进程生效；不保证代理比直连更可靠。不要关闭TLS证书验证来绕过连接问题。

## 按错误类型检查

| 现象 | 检查方向 |
| --- | --- |
| DNS、连接失败或TLS错误 | 网络、代理、目标主机连接；不能据此判断模型不支持生图 |
| 401/403 | TUZI_API_KEY或凭据库条目、令牌权限；不输出密钥 |
| 型号或参数错误 | 核对型号和Chat/Images协议，避免直接复用其他脚本参数 |
| 429或余额错误 | 检查渠道额度和限流，不自动重复提交 |
| 502等上游错误 | 保留请求标识及错误，不能只凭状态码确定根因 |
| 读取超时 | 请求可能仍在服务端处理，不代表取消或未计费 |
| API成功、CDN下载失败 | 优先恢复已有图片下载，不重新生图 |

先查看同名JSON中的endpoint、status、error和耗时，再查渠道请求/账单日志。记录为failed_or_unknown意味着状态未确定。
当前脚本不会在下载失败时保存可供自动恢复的完整响应，不应把它描述为支持断点续传。已有图片URL时可单独下载，不带API授权头。
所有排查日志与分享记录须去掉密钥，不自动切换服务商或循环尝试多个模型。
